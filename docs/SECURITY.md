# Security Guidelines

هذا المستند يوضح الممارسات الأمنية الأساسية للمشروع وكيفية التعامل مع الأسرار والمفاتيح.

1. فصل الأسرار عن الكود
   - لا تحفظ أي مفاتيح أو أسرار في المستودع. استخدم `workers/.env` محلياً (تمت إضافته إلى `.gitignore`).
   - التزم بملف `workers/.env.example` كمخطط فقط.

2. إدارة الأسرار في البيئات الحية
   - استخدم Secret Manager (GitHub Secrets, GitLab CI variables, AWS Secrets Manager أو Vault) لتمرير القيم خلال CI/CD.
   - لا تضع مفاتيح في ملفات التكوين العامة أو في Docker images المبنية.

3. إزالة المفاتيح المسربة من Git (إذا لزم)
   - إذا اكتشفت مفتاحاً في تاريخ الكوميتات، استبدله فوراً واطلع على استخدام `git filter-repo` أو `BFG Repo-Cleaner` لإزالة المفتاح من التاريخ.
   - بعد التنظيف، أعد إصدار (rotate) أي مفاتيح تم تسريبها.

4. تقليل صلاحيات المفاتيح
   - امنح كل مفتاح أقل قدر من الصلاحيات المطلوبة فقط (principle of least privilege).
   - استخدم مفاتيح خاصة بالبيئة (dev/staging/prod) منفصلة.

5. الاتصالات المنفذة عبر الـ worker
   - الـ `worker` هو المسؤول الوحيد عن حمل المفاتيح والتواصل مع موفري الذكاء/التخزين.
   - الواجهة الأمامية تتعامل فقط مع البوابة (Gateway) أو مع الـ worker عبر واجهة داخلية محمية.

6. المراجعة والتدقيق
   - قم بإجراء مسح دوري للأسرار (secret scanning) قبل الدمج إلى الفرع الرئيسي.
   - استعمل أدوات مراقبة السجلات للتعرف على محاولات الاستخدام غير المصرح بها.

---

إذا رغبت، أستطيع تضمين أوامر نموذجية `git filter-repo` لإرشاد عملية إزالة أي مفتاح سبق وتضمّن في المستودع.
